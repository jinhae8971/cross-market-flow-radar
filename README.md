# Cross-Market Flow Radar

한국 · 일본 · 유럽 · 미국 4개 시장 사이의 **스마트머니 이동**을 탐지한다.

## 설계 원칙

4개 시장은 데이터 해상도가 근본적으로 다르다. 한국은 거래소가 투자자 주체별
순매수를 일별로 공시하지만, 유럽은 그에 준하는 공시 자체가 없다.
이를 억지로 같은 축에 올리면 신호가 망가지므로 두 가지를 아키텍처에 박아 넣었다.

1. **시장마다 한 가지 측정 방식만 합산(v2).** 한국은 KOSPI 외국인 순매수,
   일본·유럽·미국은 미국 상장 국가 ETF 순설정. 원천이 빠진 날을 다른 척도로
   메우지 않는다 — 계열 안에서 척도가 바뀌면 z-score가 의미를 잃는다.
   국내 주체(기관·연기금·개인)와 COT 포지션은 합산하지 않는 맥락 지표다.
2. **날짜가 찍힌 원천만.** 기준일 없는 값은 갱신이 멈춰도 알 수 없고, 멈춘 값은
   가격수익률을 유령 흐름으로 바꾼다. 각국 원천 소스는
   접근성이 들쭉날쭉하다(KRX는 데이터센터 IP를 차단한다). 어느 하나가 죽어도
   파이프라인은 계속 돌고, 해상도만 낮아진다. 어떤 수집기가 죽었는지는
   대시보드 `수집 상태` 표에 그대로 드러난다.

## 계층

```
L0 수집   issuer(iShares·SSGA 발행좌수×NAV) · kr_investor(다음 금융) · cot · korea(KRX, 키 등록 시)
L1 저장   data/flows.parquet — (ts,market,actor,instrument,source) 업서트
L2 신호   z-score(강도) · CUSUM(체제전환) · 편차 기준 지속성
L3 로테이션  자기 변동성으로 표준화 → 점유율 → 수준+모멘텀 순위
L4 배포   docs/data.json → GitHub Pages 대시보드 + 텔레그램 브리프
```

## 발화 규칙

강도 · 체제전환 · 지속성 **3개 중 2개 이상**을 충족해야 알림이 나간다.
단발 급등은 z-score와 CUSUM을 동시에 밀어올리므로, CUSUM은 직전 기간에도
누적이 살아 있었을 때만 인정한다. 여기에 캘린더 마스크(동시만기 · MSCI
리밸런싱 · 배당락)를 얹어 기계적 매매일의 신호는 사유를 달아 억제한다.

## 데이터 소스 (v2, 2026-09-23)

| 시장 | 핵심 계열 | 원천 | 주기 | 신뢰도 |
|---|---|---|---|---|
| KR | KOSPI 외국인 순매수 | 다음 금융 investor API (KRX 키 등록 시 KRX 우선) | 일 | 0.90 |
| JP | EWJ 순설정 | iShares product screener (기준일 포함) | 일 | 0.90 |
| EU | EZU·FEZ·EWG·EWU·EWQ 순설정 | iShares + SSGA NAV history | 일 | 0.90 |
| US | SPY·IWM·DIA 순설정 | SSGA NAV history + iShares | 일 | 0.90 |
| 맥락 | 기관·연기금·개인 / EWY / COT 투기 포지션 | 다음 금융 · iShares · CFTC | 일·주 | 합산 제외 |

- 순설정 = (발행좌수_t − 발행좌수_prev) × NAV_t. 직전 관측이 바로 앞 세션일 때만 계산하고,
  관측 공백은 하루로 몰지 않는다. 발행좌수 급변(×1.5)은 분할로 보고 제외한다.
- 원관측은 `data/fund_obs.json`에 남기고 흐름은 매 실행 재계산한다(식을 고쳐도 소급 가능).
- 시장 내 순자산 커버리지 80% 미만인 날은 계열에서 뺀다(구성 변화로 분산이 흔들리지 않게).
- SSGA는 전체 이력을 주므로 미국(SPY·DIA, 순자산 92%)은 1년 소급된다. iShares는 당일
  스냅샷만 주므로 일본·유럽은 2026-09-22 첫 관측부터 누적된다(z20은 8세션부터).
- USD 환산은 ECB 기준환율(Frankfurter), 실패 시 yfinance.
- VGK·QQQ·BBJP·DXJ·FLKR은 기준일이 찍힌 일별 원천을 확보하지 못해 v2에서 제외했다.

### v1 데이터를 걷어낸 이유
yfinance `totalAssets` 기반 추정치(`etf_aum_delta`)를 SSGA 공시와 대조한 결과
(2026-08-11~09-08) SPY 상관계수 −0.11, 20세션 합계 +$25.9B(실제 −$0.1B),
FEZ는 실제 설정 0인데 매일 값이 찍혔다. 대리지표(`etf_moneyflow_proxy`)와 폐기된
네이버 PC 페이지(`naver_kr`, HTTP 410) 행과 함께 저장소에서 제거한다(git 이력에는 남는다).

## 실행

```bash
pip install -r requirements.txt
python run.py            # 일상 실행 (발행 보류도 정상 종료)
python run.py --seed     # 한국 이력을 100영업일 다시 받기
python notify.py         # 텔레그램 브리프
python -m unittest discover -s tests
```

## 전달 방식

텔레그램은 **결론만**, 대시보드는 **그 결론의 근거**를 담는다.

- 브리프: 로테이션 방향 · 발화 신호 · 시장별 순유입 4줄 · 대시보드 링크
- 대시보드: 시장 레인을 누르면 상세가 펼쳐진다
  누적(5/20/60일) · 신호값과 임계치 게이지 · 기여 종목 · 자금 주체 · 출처별 신뢰도

## 배포

```
Secrets:   TELEGRAM_TOKEN · TELEGRAM_CHAT_ID · KRX_API_KEY(선택)
Variables: DASHBOARD_URL (미설정 시 GITHUB_REPOSITORY로 Pages 주소 자동 조립)
등록 위치: https://github.com/<user>/<repo>/settings/secrets/actions
```

Variables: MIN_CONFIDENCE (발행 게이트, 기본 0.60)

### 운영 (v2)
- 스케줄: 평일 15:17 KST(주 발송) · 16:47(공시 지연 재시도) · 08:17(누락분 따라잡기).
  SSGA는 미국 세션 T 값을 KST T+1 약 14:00에 올린다.
- 게이트: 신뢰도 = 시장 품질 평균 × 커버리지(관측 시장/4). 3개 시장이면 0.675,
  2개면 0.45. `MAX_STALE_SESSIONS=2`를 넘겨 뒤처져도 보류.
- **저장과 발행 분리.** 보류여도 관측은 저장·커밋된다(v1은 보류 시 커밋이 건너뛰어져
  기준점이 갱신되지 않는 흡수 상태에 빠졌다).
- 텔레그램은 상태 전환에만: 새 기준일 브리프 1회, 보류 전환 1회 + 7일 재알림,
  워밍업 안내 1회. KST 22:00~07:00 발송 금지. 결손 시장이 있으면 12~16시엔 공시 대기.
- 워크플로우 자체 실패(테스트·예외)는 2회 연속부터, 20시간에 1회만 알린다(`ops_alert.py`).
- Pages는 `docs/` 디렉터리를 소스로 지정한다.

## 데이터 품질 보강 (2026-09-09) — v2에서 대체됨

AUM이 이전 스냅샷과 같거나 일부 누락/비정상이면 전체 ETF 배치의 흐름 계산을 보류하고 캐시를 보존합니다. 이는 실제로 AUM이 같았던 경우에도 보수적으로 보류할 수 있습니다. 세션 공백은 새 기준점만 설정하며 여러 날의 변화를 하루 흐름으로 기록하지 않습니다. 수집 실패 시 신규 알림과 로테이션 판단을 보류하며, 새 ETF 관측 전에는 경고를 유지합니다. KRX 0건은 원천 수급 미수집으로 표시합니다.

9/8 기존 산출물에는 AUM 미갱신 의심 경고를 표시했습니다. 원시 이력은 삭제하거나 추정값으로 재작성하지 않았습니다. totalAssets 자체에 공급자 기준일이 없으므로 향후 공식 일별 NAV/발행주식수 데이터로 교차 검증이 필요합니다.
